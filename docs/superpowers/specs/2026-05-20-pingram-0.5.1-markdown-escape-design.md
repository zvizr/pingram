# Pingram 0.5.1 — MarkdownV2 Escape Helpers Design

**Status:** Approved for implementation
**Target version:** 0.5.1 (patch)
**Previous release:** 0.5.0 (2026-05-20, this same day)

---

## Context

Pingram 0.5.0 shipped sync + async clients but offers no help with Telegram's MarkdownV2 escaping rules. MarkdownV2 requires backslash-escaping for a long list of characters (`_*[]()~`>#+-=|{}.!` plus `\`) when they appear in normal message text, and a different (smaller) set inside inline code spans and link URLs. Users currently either skip MarkdownV2 entirely or roll their own escape function — a recurring footgun.

0.5.1 ships three small helpers, one per MarkdownV2 context. No fanfare. No API breakage. No async/sync split — they're pure functions.

## Goals

1. Provide three public, well-named, single-purpose helpers for MarkdownV2 escaping.
2. Cover all three escape contexts the Telegram spec defines (text, code, link URL).
3. Keep the patch tiny: ~30 lines of code, ~30 lines of tests, no new dependencies.
4. Preserve 100% backward compatibility — no changes to `Pingram`, `AsyncPingram`, or the exception hierarchy.
5. Document with a short README section so users discover the helpers without reading the source.

## Non-Goals

- HTML-mode escaping (`parse_mode="HTML"` requires different rules — save for a future release if anyone asks).
- Auto-escape mode on `Pingram.message(..., auto_escape=True)` — too magical, would break template syntax users intentionally include.
- A `pingram.markdown.Template` class or any template engine (explicitly out per brainstorming).
- Async helpers — the functions are pure, no IO, no `await`.

## Architecture

### Module layout

```
src/pingram/
├── __init__.py          # add three re-exports
├── pingram.py           # unchanged
├── async_pingram.py     # unchanged
├── _errors.py           # unchanged
├── _retry.py            # unchanged
└── markdown.py          # NEW — three pure functions, ~30 lines
```

`markdown.py` has **no underscore prefix** because its contents are part of the public API surface. The convention in this codebase is: leading underscore on a module name means "internal, do not import directly" (e.g. `_errors`, `_retry`). The exception types are re-exported from those, but the modules themselves are private. By contrast, users may legitimately want to import from `pingram.markdown` directly if they want only the escape helpers without pulling in the full client.

### Public API

```python
# Direct import (encouraged):
from pingram import escape_markdown_v2, escape_markdown_v2_code, escape_markdown_v2_link_url

# Or via the module:
from pingram.markdown import escape_markdown_v2
```

All three are added to `__all__` in both `pingram.markdown` and `pingram` (top-level).

### Function signatures and contracts

| Function | Escapes | Use inside |
|---|---|---|
| `escape_markdown_v2(text: str) -> str` | `_*[]()~`>#+-=\|{}.!` and `\` | Plain MarkdownV2 message body |
| `escape_markdown_v2_code(text: str) -> str` | `` ` `` and `\` | Inline code span: `` `...` `` and pre block: ` ```...``` ` |
| `escape_markdown_v2_link_url(url: str) -> str` | `)` and `\` | The URL part of a link: `[label](URL)` |

All three:
- Accept `str`, return `str`
- Are idempotent on inputs that contain no special characters
- Are **not** idempotent on inputs that already contain `\` escapes (`escape_markdown_v2("\\_")` returns `"\\\\\\_"`, not `"\\_"`). This matches the principle of least surprise: the helper escapes for you; it does not detect prior escaping.
- Raise `TypeError` from `_escape`'s internal `"".join(...)` only if a non-string is passed (the natural Python behaviour; no extra validation needed).

### Implementation

Single private helper plus three public wrappers:

```python
# pingram/markdown.py

# Telegram MarkdownV2 spec: https://core.telegram.org/bots/api#markdownv2-style
# Frozensets avoid the raw-string-with-trailing-backslash trap and give O(1)
# membership for the per-character loop.
_TEXT_SPECIAL_CHARS = frozenset("_*[]()~`>#+-=|{}.!\\")
_CODE_SPECIAL_CHARS = frozenset("`\\")
_LINK_URL_SPECIAL_CHARS = frozenset(")\\")


def escape_markdown_v2(text: str) -> str:
    """Escape text for use inside a MarkdownV2 message body."""
    return _escape(text, _TEXT_SPECIAL_CHARS)


def escape_markdown_v2_code(text: str) -> str:
    """Escape text for use inside an inline code span or pre block."""
    return _escape(text, _CODE_SPECIAL_CHARS)


def escape_markdown_v2_link_url(url: str) -> str:
    """Escape a URL for use inside the (...) part of a MarkdownV2 link."""
    return _escape(url, _LINK_URL_SPECIAL_CHARS)


def _escape(text: str, special_chars: frozenset[str]) -> str:
    return "".join("\\" + c if c in special_chars else c for c in text)
```

The `_escape` helper iterates once per character with `frozenset` lookups. Telegram's per-message cap is 4096 chars, so the cost is bounded and trivial; no need for a precompiled regex.

## Testing

`tests/unit/test_markdown.py` covers:

- `escape_markdown_v2`:
  - Empty string returns empty string
  - String with no special chars is unchanged
  - Every special character escapes correctly (parametrized over the 18 special chars)
  - Mixed string with multiple specials: `Hello *world*!` → `Hello \*world\*\!`
  - Real-world: `my_username` → `my\_username`
  - Real-world: phone-like: `(123) 456-7890` → `\(123\) 456\-7890`
  - Backslash itself: `a\\b` → `a\\\\b`
- `escape_markdown_v2_code`:
  - Backtick: `` `cmd` `` → `` \`cmd\` ``
  - Slashes, parens, etc. pass through: `/tmp/x_y` → `/tmp/x_y` (unchanged)
  - Backslash: `\` → `\\`
- `escape_markdown_v2_link_url`:
  - Closing paren in URL: `https://x.com/q=(a)` → `https://x.com/q=(a\)`
  - URL with no special chars passes through unchanged

Roughly 12 test cases total. Existing `tests/unit/` test patterns (no `mock_api` needed — these are pure functions).

## Risk assessment

| Risk | Likelihood | Mitigation |
|---|---|---|
| Function names too long, friction discourages use | Low-medium | Three short examples in README; long names trade typing for grep-ability and clarity |
| Users escape the same string twice and get double-escaped output | Medium | Documented: helpers are NOT idempotent on already-escaped input. README example shows the f-string pattern that's the intended use. |
| The 18-char text list drifts from Telegram's spec over time | Very low | Telegram has not changed the MarkdownV2 spec since publication. If they do, a one-line constant update + new test ship in 0.5.2. |
| Hot loops over very long strings get slow | Very low | Telegram caps at 4096 chars/message; the per-char loop is fine. Switch to precompiled `re.sub` only if profiling ever flags it. |
